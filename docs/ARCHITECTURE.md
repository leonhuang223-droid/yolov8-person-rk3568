# 设计说明与扩展位置

## 参考项目的继承和改善

参考 `yolov8-helmet-rk3588-multithread-main` 的固定检测 worker 思路，以及 `22_yolov8/yolov8` 的 context 复制/输入内存绑定思路。新项目为 RK3568 单核 NPU 编写，去掉 RK3588 core mask 假设，模型接口严格对应现有行人模型。

原项目审阅记录见工作区 `RK3568_YOLOv8_REVIEW.md`。新实现修正或避免了重复 sigmoid、输出索引不完整、80 类/640 输入硬编码、手动释放 SDK 输出、轮询等待、结果无限积压，以及以提交数或线程 FPS 相加估计吞吐的问题。未直接把参考项目的业务文件复制进新目录。

## 工厂与职责

| 工厂 | 当前实现 | 将来的扩展 |
|---|---|---|
| InputSourceFactory | 单图/目录、OpenCV FFmpeg 本地视频 | MPP 解码、摄像头、RTSP |
| PreprocessorFactory | OpenCV、RGA、兼容性自动回退 | DMA 图像源、自定义预处理 |
| EngineFactory | 普通输入 API、RKNN 内存绑定输入、自动探测 | 新模型契约、绑定输出 |

Frame 包含帧号、来源、时间戳、所有权明确的图像和读取时刻。FrameResult 包含多人检测框、工作模式、分阶段耗时和检测完成时刻。后处理核心不依赖 OpenCV、RGA 或 RKNN，便于在主机测试。

工厂创建发生在启动阶段；模型错误不会触发“成功”的自动回退。自动输入模式先验证普通输入推理，之后用复制 context 验证绑定路径，失败时保留普通引擎。自动 RGA 模式以真实帧尺寸验证，首次失败后该 worker 固定使用 OpenCV，避免每帧反复失败和打印。

## 帧槽与并发

固定数量的帧槽在 free queue、producer、task queue、worker、reorder map 和 writer 之间转移。只有输出完成后才能归还槽，所以即使任务队列已经空了，读取端也无法越过总在途帧限制继续解码。

检测线程把结果提交到 map 时不等待空位：结果的数量已由帧槽限制。这样不会出现“后续帧占满结果队列，最早帧的 worker 无法提交，writer 又在等最早帧”的死锁。

EOF 关闭任务队列，worker 继续排空，最后一个 worker 通知 writer。writer 按连续帧号消费所有结果后退出。任一读取、检测或输出异常保存首个错误，取消两个阻塞队列并唤醒排序等待者，随后 join 所有已创建线程。成功退出还会核对提交和输出计数。

终止信号先由主线程屏蔽，解码器、Runtime 和应用线程均继承屏蔽状态；独立 sigwait 线程执行普通上下文取消，避免在异步 signal handler 中操作 mutex/condition_variable。

## 内存与性能边界

输入、九输出缓冲和 DFL/NMS 候选工作区归 worker 所有；图像缓冲归帧槽所有。图片读取会临时产生一个 imread 解码结果并复制到复用槽，视频直接解码到槽。标注直接修改已结束检测的原图槽，直到编码完成才归还。

零拷贝名称只用于“绑定输入”这一层：OpenCV 输入仍会写 RGB 缓冲；RGA 的图像源仍是 OpenCV 的虚拟地址，绑定输入使用 RKNN 的 FD。模型输出仍由普通 API 直接填预分配用户缓冲，不额外复制成后处理数组。没有声称整条视频链路零拷贝。

RK3568 只有单核 NPU，增加 worker 的价值主要是重叠 CPU 预处理/后处理和 NPU 等待。它也会增加工作内存与 CPU 争用，因此默认一个 worker，最终按相同输入的板端测量选择数量。

新增实时输入时，应重新定义背压/丢帧和时延需求；不要把离线完整输出队列直接用于无限输入。新增模型时，先扩展接口验证及参考解码测试，再修改工厂，不应绕过现有九输出检查。
